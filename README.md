# SAN3TY — Smart Home Services Platform

منصة عربية تربط العملاء بمقدمي الخدمات المنزلية، مع تجربة RTL متجاوبة وهوية بصرية خاصة.

## تجربة العميل
- اختيار الخدمة يدويًا عبر نموذج الطلب الحالي.
- مسار مساعد ذكي يقبل صورة أو وصفًا نصيًا للمشكلة.
- تحليل أولي باللغة العربية مع احتمالات وخطوات آمنة وتنبيه للحالات عالية الخطورة.
- ترشيح صنايعية من قاعدة البيانات فقط: موثقون، متاحون، يقدمون التخصص المطلوب، ويغطون المدينة والمنطقة.
- ترتيب النتائج بناءً على التقييمات وعدد المراجعات والأعمال المكتملة.

## القيمة التجارية
يعرض الموقع مزايا SAN3TY للعملاء والصنايعية، ونموذج إيرادات مقترح يشمل عمولة الطلبات المكتملة، اشتراكات مقدمي الخدمة، الظهور الترويجي المعلن، رسوم خدمة شفافة، عقود صيانة B2B وشراكات الموردين. هذه مصادر دخل مقترحة وليست أرباحًا محققة.

## هيكل المشروع
- `index.html`, `styles.css`, `app.js`: الموقع والواجهة.
- `config.js`: إعدادات Supabase العامة للمتصفح فقط.
- `supabase/schema.sql`: مخطط قاعدة البيانات.
- `supabase/migrations/20261120_add_ai_matching.sql`: إضافة RPC للاكتشاف وحد الاستخدام لمشروع قائم.
- `supabase/functions/diagnose-request/index.ts`: واجهة AI آمنة من جهة الخادم.
- `supabase/config.toml`: إعداد Edge Function.

## التفعيل
اتبع `AI-SETUP.md` لتشغيل Gemini وربط Supabase. لا تضع أي مفتاح سري في ملفات المتصفح أو GitHub. Edge Function تحتاج سر `GEMINI_API_KEY` وسر Supabase الخادمي. قاعدة البيانات تحتاج صنايعية حقيقيين موثقين في المناطق المستهدفة.

## الحالة الحالية
واجهة المساعد وقسم نموذج الإيرادات جاهزان في الكود، لكن التحليل الفعلي والترشيح لن يعملا حتى إنشاء مشروع Supabase وتشغيل SQL ونشر Edge Function وإضافة مفاتيح الاتصال. الحجوزات والمدفوعات وتسجيل الدخول ما زالت تحتاج تنفيذ Backend منفصل واختبارات قبل الإطلاق التجاري.

راجع `SECURITY.md` قبل استقبال صور أو بيانات عملاء.
