# SAN3TY — Smart Home Services Platform

منصة عربية لطلب الخدمات المنزلية تربط العملاء بمقدمي الخدمات، مع تجربة RTL متجاوبة وهوية بصرية مميزة. هذا المستودع يحتوي على الواجهة الأمامية التجريبية، مخطط قاعدة بيانات Supabase، وإعداد النشر التلقائي عبر GitHub Pages.

> **حالة المشروع:** Prototype / Demo. الواجهة تفاعلية وتعمل في المتصفح، لكن تسجيل الحسابات والطلبات والحجوزات والدفع والذكاء الاصطناعي غير متصلة بخدمات خلفية حقيقية حتى الآن.

## محتويات المشروع

- واجهة عربية RTL متجاوبة مع حركات انتقال وظهور.
- أقسام الخدمات المنزلية ورحلة طلب الخدمة.
- مساعد محادثة تجريبي بإجابات مبرمجة مسبقًا (ليس نموذج AI متصلًا).
- نموذج طلب خدمة ونموذج انضمام مقدم الخدمة يعملان محليًا للعرض فقط.
- مخطط PostgreSQL لـ Supabase يشمل الملفات الشخصية، التصنيفات، الصنايعية، الطلبات، الحجوزات، الرسائل، التقييمات ومراجع الدفع.
- سياسات Row Level Security (RLS) وصلاحيات أعمدة مبدئية لتقليل صلاحيات العميل.
- GitHub Actions workflow للنشر على GitHub Pages.

## تشغيل الموقع محليًا

1. افتح المستودع في VS Code.
2. افتح `index.html` مباشرة في المتصفح، أو شغّل Live Server.
3. لا توجد حاجة إلى `npm install` أو خطوة build.

يستخدم الموقع خطّي Alexandria وManrope من Google Fonts؛ عند عدم توفر الإنترنت سيستخدم خطوطًا بديلة.

## النشر على GitHub Pages

تم إعداد `.github/workflows/static.yml` للنشر التلقائي عند كل `push` إلى `main`، مع إمكانية التشغيل اليدوي.

1. افتح **Settings → Pages** في المستودع.
2. اختر **GitHub Actions** ضمن Build and deployment.
3. افتح تبويب **Actions** وتأكد من نجاح مهمة `Deploy SAN3TY to GitHub Pages`.
4. بعد نجاح النشر ستجد رابط الموقع في إعدادات Pages وفي تفاصيل تشغيل الـ workflow. غالبًا سيكون بالشكل `https://YOUR-USERNAME.github.io/san3ety/`.

## إعداد قاعدة بيانات Supabase

ملف `supabase/schema.sql` هو مخطط قاعدة البيانات، وليس قاعدة بيانات مستضافة أو مشروع Supabase جاهزًا. لتشغيله:

1. أنشئ مشروعًا جديدًا في Supabase.
2. افتح **SQL Editor** وشغّل محتوى `supabase/schema.sql` على المشروع الجديد.
3. راجع سياسات RLS والصلاحيات بحسب تدفقات العمل الفعلية قبل فتح التسجيل العام.
4. انسخ Project URL و`anon` / publishable key فقط إلى إعدادات الواجهة عند بناء طبقة الربط.
5. نفّذ العمليات الحساسة من خلال Edge Functions أو Backend موثوق.

### ملاحظات أمنية مهمة

- لا تضع `service_role` أو أي مفتاح سري في ملفات الواجهة أو GitHub.
- سياسات RLS وصلاحيات الأعمدة الموجودة هي نقطة بداية، وليست بديلًا عن مراجعة أمنية واختبارات قبل الإنتاج.
- صلاحيات تأكيد الحسابات والتحقق من الصنايعية وتعيين الحجوزات وتحديث حالات الدفع يجب أن تكون على الخادم.
- جدول `payment_records` يخزن مرجع وحالة الدفع فقط؛ لا يحتجز أموالًا ولا ينشئ نظام Escrow.
- لا توجد حاليًا بيانات شخصية حقيقية أو مفاتيح API داخل هذا المستودع.

## ما يلزم قبل الإطلاق الفعلي

- توصيل Supabase Auth وإنشاء طبقة API آمنة للنماذج والطلبات.
- استكمال تقديم طلب انضمام الصنايعي والتحقق من الهوية والمهنة.
- تنفيذ محرك المطابقة وتدفق الحجز وتحديث الحالات على الخادم.
- توصيل مزود دفع مناسب والتحقق من Webhooks من الخادم، مع مراجعة قانونية وتشغيلية.
- توصيل مساعد AI من خلال Backend لحماية مفاتيح النماذج، واختبار دقة التقديرات.
- إضافة اختبارات، مراقبة، نسخ احتياطية، سياسة خصوصية، وشروط استخدام وآلية فض نزاعات.
